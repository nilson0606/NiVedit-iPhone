## 0.1.5 更新：匯出競態與秒數顯示
使用者回報偶爾匯出失敗（720p 也會）、重開後正常，且不確定是否重複按到；失敗訊息與異常秒數位置未記得。本機已重現以下程式缺陷，但無法斷言就是使用者當次失敗的唯一原因。
- 修正 releaseResult 在 await 後讀取共用 jobId：上一輪清理曾刪到新一輪成品。現在先同步取出舊 ID 並清空共用參照，之後只清理該舊 ID。
- 修正取消後快速重試、前一輪 Wake Lock Promise 較晚回來時，舊流程可能再啟動一個 Worker。每次匯出使用獨立序號，取消／失敗後舊流程失效。
- 單純連點開始按鈕原本已被 busy 擋住；加入明確回歸測試，確認只啟動一個工作。
- 每次匯出固定來源與專案設定快照，驗證成品使用同一份快照。
- 匯入期間暫停舊影片秒數更新與 Undo／Redo；播放秒數限制在剪輯區間。
- 修正 formatTime(59.96) 曾顯示 00:60.0，現在正確為 01:00.0；此為獨立確認的格式缺陷，不能當作已確認使用者描述的秒數根因。
- 最近一次匯出錯誤、階段、尺寸、剪輯區間及驗證結果保存在本機診斷，重開後仍能複製；沒有上傳素材或診斷。
- 測試結果：6 項模型測試、29 項瀏覽器流程、7 項升級檢查均通過；專門競態測試確認誤刪新檔 true→false、取消重試啟動工作數 2→1、連點工作數為 1，失敗後不重開即可匯出，診斷可跨重開保留。
- 證據在 qa/race-before.json、qa/race-after.json；可重跑 tests/export-race.cjs。iPhone 間歇性失敗是否完全解決，仍需使用者實機回報。

## 0.1.4 更新：修正舊版快取與提供更新入口
使用者回報關閉再開仍顯示 0.1.2。程式檢查發現舊流程採 cache-first、缺少明確啟用入口，且預快取未避開瀏覽器 HTTP 快取；使用者實機的確切 SW 狀態未取得，不宣稱已在其裝置直接定位單一根因。
- 新增 update.html 獨立更新頁，無需依賴可能過期的主程式。按「更新並重新開啟」才啟用等待中的版本。
- 新版的「裝置」及更新提示提供入口，先成功儲存草稿才跳轉；匯出／匯入中阻止跳轉。
- Service Worker 下載各資源使用版本 query 與 no-store，並依 release.json 驗證每個資源 SHA-256；檔案不齊或版本混合時拒絕安裝。
- 保持同一個 SW scope，不另建有衝突的註冊。不呼叫 unregister，也不刪除 IndexedDB 草稿或 OPFS 素材；只清除本 App 舊版應用快取。
- 更新完成以版本 query 重新開啟首頁，新 worker 將導向同一套已驗證的快取。
- 舊版開著時不強制刷新編輯頁，使用者選擇更新後才切換；版本檢查失敗可重試。
- Windows Edge 升級回歸 7 項通過：0.1.2 真實舊程式＋長效 HTTP 快取 → 0.1.4、舊頁仍開著時手動升級、草稿欄位與原媒體 SHA-256 不變、恢復後新控制可用、請求繞過舊 HTTP 快取、離線重開、混合資源拒絕安裝。
- 測試：tests/update.cjs；記錄 qa/update-report.json。iPhone 最終更新結果仍待使用者確認。
- 發布前必須更新版本並執行 python scripts/release.py，之後若再改應用／手冊／圖示，要重新產生雜湊再提交。

## 0.1.2 更新：手動選擇畫面方向
- 修正上一版只有依來源自動判斷、無法手選方向的不足。
- 「匯出」視窗可選橫向 16:9／直向 9:16，與 720p／1080p 畫質自由搭配。
- 匯入時仍依來源設定初始方向，之後以使用者選擇為準；切換畫布方向不旋轉來源，也不裁切來源。
- 預覽影片外框同步所選畫布比例，與匯出同樣保留完整畫面、以黑邊補足。
- 方向寫入草稿，支援復原／重做，改動後清除舊匯出；匯出中鎖定方向選單。
- Windows Edge 瀏覽器檢查 26 項、模型檢查 5 項通過。FFmpeg 驗證橫片→1080×1920 直向畫布及直片→1920×1080 橫向畫布，均保留 AAC、中央有效畫面與正確黑邊。
- 使用者的 iPhone 720p 基本流程已通過；新增方向選項仍待使用者實機確認。

## 0.1.1 更新：可選 1080p
- 匯出視窗新增畫質選擇：720p（預設，4 Mbps）／1080p（8 Mbps），皆為 30 fps。
- 1080p 橫向 1920×1080、直向 1080×1920，沿用原聲 AAC 192 kbps。
- 畫質選擇寫入草稿，支援復原與重做；更改設定即清除舊匯出成品。
- 匯出前探測所選尺寸的 H.264 編碼能力；不支援就報錯，不自動降回 720p。
- 完成後額外驗證實際輸出寬高；低解析度來源放大不會增加原有細節。
- Windows Edge 驗證：21 項瀏覽器檢查、4 項模型檢查通過；FFmpeg 獨立解碼確認兩方向解析度、30 fps、AAC 音軌及首中尾非黑畫格。
- 1080p 的 iPhone 實機回報尚待確認。先前使用者通過的是 0.1.0 的 720p 核心流程，不能直接沿用為 1080p 的實機證據。
- Service Worker 快取版本更新至 0.1.1；不強制重載剪輯中的頁面。若仍顯示舊版，先確認草稿已儲存，關閉本站所有分頁／主畫面 App，再重新開啟。

## 技術取捨
保留 V13 inP/outP/at/track/proj 等資料語意，未直接載入綁定桌面 DOM 的全域程式。
媒體後端使用固定且自行託管的 Mediabunny 1.58.1，避免桌面 demuxMP4 一次讀入完整 ArrayBuffer，以及全片 OfflineAudioContext 混音的記憶體模式。
此階段只處理單片原聲，無新增合成語意；之後加入多軌時須抽出 V13 合成規則，不能用簡單串接取代。
檔案只在本機處理，沒有後端、API 金鑰或雲端上傳。
Repository 跟網址均獨立，IndexedDB／CacheStorage 命名與桌面分開。GitHub Pages 同一帳號的不同路徑仍是相同 origin，不宣稱為瀏覽器安全隔離。
