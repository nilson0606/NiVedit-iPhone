## 2. 最終交付的定義

最終交付的是可以在 iPhone Safari 與加入主畫面模式使用的剪輯 Web App。使用者能完成 V13 原本的操作、保存可編輯專案，以及得到相同編輯語意的成品。操作入口可以重新設計，不要求按鈕位置與 Windows 相同。

功能對齊至少分成四項逐一驗證：

- **操作對齊**：觸控能完成桌面原有操作，不能依賴滑鼠右鍵、懸停或實體鍵盤。
- **資料對齊**：V13 專案 → iPhone → V13，素材與編輯參數不遺失。
- **結果對齊**：同一專案的疊放、裁切、轉場、GIF 相位、字幕及音量曲線相符。
- **平台對齊**：檔案選取／分享等採用手機合理流程；不能把「編碼完成」冒充「已存入照片」。

可調低預覽解析度或使用代理檔提升速度，但正式輸出設定及原素材要保留。若要變更輸出解析度、模型或格式，應告知並讓使用者選擇。

### 必須提早處理的邊界

V13 包含獨立的 Windows YT → MP3 輔助程式。iPhone 網頁不能直接執行現有 Python／VBS／Windows FFmpeg；iPhone 的 `127.0.0.1` 也不是使用者的電腦。因此：

- 這項功能仍在最終需求內，不能只留一個下載 Windows 安裝包的按鈕就算移植完成。
- 第一階段先提出可行架構，後續再正式實作，避免到最後才發現不成立。
- 可研究經使用者核准的獨立服務，或經配對的桌面輔助端；兩者都屬於「需要外部支援」的方案，**不等於 iPhone 自己獨立完成**。
- 若要求同時是純靜態 GitHub Pages、完全手機本機處理、無任何輔助端，不能承諾此工具原樣可行；它必須留在未解決清單，請使用者決定架構，不得默默刪除。
- 新增外部處理不代表可以自動上傳剪輯素材、憑證或瀏覽器登入資料。資料流、部署及費用需另行確認。

同樣地，Turbo 模型、4K 匯出、原生檔案覆蓋也不能只用「平台不支援」一句話結案：要提出實測、替代流程與尚缺能力，保留驗收項目。

## 3. iPhone UI 重新規劃

### 3.1 直向為主要流程，橫向為擴充工作區

建議直向配置：

```text
┌──────────────────────────┐
│ 專案名稱／儲存狀態   儲存 匯出 │
├──────────────────────────┤
│                          │
│          預覽畫面          │
│                          │
├──────────────────────────┤
│ 回開頭  播放  時間碼  到結尾   │
├──────────────────────────┤
│ 固定軌道名稱 │ 可捲動時間軸   │
│ 多軌可垂直捲動；可調區域高度   │
├──────────────────────────┤
│ ＋素材  編輯  文字  音訊  更多 │
└──────────────────────────┘
選到項目 → 底部屬性面板可半展開／全展開
```

- 頂列只保留專案、儲存、匯出等必要操作。新建、開啟、另存、範例、設定、日夜、語言、手冊及獨立工具放進清楚的專案／更多選單。
- 素材面板區分影片、圖片、動畫效果、音樂；動畫與音樂都保留「內建／自己的檔案」。
- 屬性以「時間、構圖、裁切、關鍵幀、转場、風格、聲音」分頁或分組；依選取類型顯示，不能因手機空間小就省掉參數。
- 一般編輯可同時看預覽和局部時間軸。字幕大量輸入、完整素材库及複雜設定可用全螢幕面板，關閉後回到原選取／播放頭／捲動位置。
- 橫向讓預覽與屬性並列，時間軸在下方；旋轉裝置只改排版，不重建專案或重置播放頭。
- 夜間預設，提供白天模式並記住偏好；繁中／英文沿用桌面語意。關鍵幀起點／終點的底色兩種主題都必須看得清楚。
- 使用 safe-area、動態 viewport 和鍵盤可視區調整，避免瀏海、Home indicator、網址列或軟鍵盤蓋住儲存／套用按鈕。不要靠鎖死頁面缩放來解決排版。
- 主要觸控區建議至少 44×44 CSS px；軌道視覺可緊湊，但裁切把手與關鍵幀節點的命中範圍要加大。

### 3.2 觸控操作契約

| 桌面操作 | 手機主要做法 | 精確操作／替代入口 |
|---|---|---|
| 點选物件 | 單指點選；顯示選取框與上下文工具列 | 重疊區可開「此處的項目」清單逐一選取 |
| 拖動播放頭 | 拖時間尺或明確的播放頭把手 | 時間碼輸入、前後一幀 |
| 移動片段 | 選取後拖片段移動把手；與橫向捲動分開 | 編輯起點秒數、「現在」、「接上一段」 |
| 裁切時間／改長度 | 選取後才出現較大左右把手 | 起點／終點／長度數字欄 |
| 滾輪捲動、Ctrl＋滾輪 | 空白區單指水平捲動；雙指捏合縮放時間軸 | ＋／－、符合視窗 |
| 右鍵、雙擊 | 長按選單作捷徑 | 必須也有可見的新增、刪除、分割等按鈕 |
| 刪音量點 | 選取節點後按刪除 | 節點列表可輸入時間／倍率 |
| 九宮格對位 | 保留可點按的九宮格 | 數字輸入位置；起終點分清楚 |
| 路徑關鍵幀菱形 | 放大命中區，可拖時間位置 | 動態開始／結束時間輸入 |
| Undo／Redo | 明確按鈕 | 手勢只能是額外捷徑，不能成為唯一入口 |

手勢先確定目標再編輯，設定拖動閾值和取消行為；一次拖曳形成一次 Undo，不能每個 pointermove 堆一筆。只在編輯區限制必要的 `touch-action`，保留面板捲動與系統導覽。

### 4.2 媒體與輸出先驗證

- WebKit 官方已記錄 Safari 26.0 加入 WebGPU，以及 WebCodecs 的 AudioEncoder／AudioDecoder。不能再沿用「iPhone 一定沒有 WebGPU／音訊編碼」的舊假設；但 API 存在不代表每種 codec／設定都能成功。[Safari 26.0 官方說明](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)
- 建議第一階段先以 iOS／Safari 26 系列或更新穩定版作主要驗證目標，最低支援版本須待裝置與實測確認。這不是宣稱 26.0 就必然能跑完整 V13。
- 檢查 VideoEncoder、AudioEncoder 的具體 `isConfigSupported()` 組合，並真正編碼、封裝、重新播放一支有聲測試片。裝置、瀏覽器版本、容器、codec、尺寸、fps 都記錄。
- 優先研究 WebCodecs＋muxer。MediaRecorder 只能作驗證過的替代路徑，不能假設錄 Canvas 就能提供相同的逐幀準確度與離線匯出效率。Safari 18.4 已擴充 MediaRecorder 的 WebM 等支援，但仍須查具體 MIME 能力與成品播放。[Safari 18.4 官方說明](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/)
- 必須區分「素材可播放」「可抓取畫格」「可編碼指定格式」「成品可保存／分享」。HEVC／HDR、方向資訊及可變影格率都要分別測。
- V13 匯出使用 `ArrayBufferTarget`／in-memory fastStart，混音使用 OfflineAudioContext；大檔手機版不能原樣假設安全。逐步改為有背壓的畫格管線、分段音訊處理及經驗證的 OPFS／串流寫入後端。
- 不在記憶體保留整支影片的 RGBA 畫格。單張 4K RGBA 約 32 MiB，幾個緩衝就有顯著負擔；影片、GIF、模型及成品緩衝不能同時無限制持有。
- 保留原片，以較低解析度代理預覽；正式輸出再用原片。代理、縮圖、波形可以清理，專案依賴的原素材不能當快取清掉。
- 切到背景、鎖屏、電話／音訊中斷、記憶體壓力都列為必要測試。設計暫停／失敗回復與檢查點，不承諾網頁在背景持續編碼。Wake Lock 只能能力偵測後輔助使用。
- 缺影像、音訊編碼失敗時指出素材或階段，不能默默匯出黑畫面或無聲影片。

### 4.3 檔案與資料安全

OPFS 是網站私有儲存，不等於使用者在 Files 裡看見的資料夾。其 API 與實際檔案選取／另存能力不能混為一談。[WebKit OPFS 說明](https://webkit.org/blog/12257/the-file-system-access-api-with-origin-private-file-system/)

建議把三種儲存分清楚：

1. **儲存專案**：更新 Web App 內的可編輯專案，採交易式寫入、寫完再切換有效版本。
2. **另存專案**：建立獨立副本；不改內建範例。
3. **匯出專案檔／影片**：產生可交給 Files、分享面板或下載流程的實體檔案，方便備份與跨裝置。

不要假設 `showDirectoryPicker` 或 `showSaveFilePicker` 一定存在。存在就探測使用，否則使用檔案選取與經驗證的分享／下載流程；不能偽造已取得外部檔案覆蓋權限。

影片編碼完成後保留產物，再由使用者按「儲存／分享」觸發系統操作；先檢查 `navigator.canShare({files})`，失敗可再試或下載。分享需要使用者觸發，不能在長時間編碼結束後假設原點擊授權仍存在；分享成功也不代表已存入照片。[W3C Web Share](https://www.w3.org/TR/web-share/)

WebKit 的儲存有配額與清除政策；加入主畫面不代表資料永不消失。使用 `estimate()` 顯示用量、嘗試 persistent storage、處理 QuotaExceededError，並保留專案檔備份出口。[WebKit 儲存政策](https://webkit.org/blog/14403/updates-to-storage-policy/)

### 4.4 PWA 與部署

- HTTPS、Web App Manifest、圖示、明確的安裝說明；Safari 頁面和主畫面模式都要實測。
- Service Worker 先快取應用外殼，再按需快取素材。不要安裝時一口氣下載 240 組動畫、41 首配樂、範例和所有 Whisper 模型。
- 專案資料與可再下載快取分開；提供快取管理，避免「清快取」連專案也刪掉。
- 更新不能在剪輯／匯出中強制 reload；提示有新版本，完成儲存再切換。保留 schema 遷移與版本回復策略。
- GitHub Pages 子路徑、相對網址、manifest scope、service worker scope 都要測。手機版採獨立發布位置，未核准前不取代桌面入口。
- 若需要自訂 HTTP headers、跨來源隔離或後端服務，先驗證選定 hosting 是否能提供；不能把 WASM 多執行緒當作 GitHub Pages 上預設可用。

## 6. 分階段交付

### 第一階段：手機骨架＋真正能匯出有聲影片

**完成內容**

- 獨立手機工作區、版本標記、HTTPS 預覽站及基本 PWA 外殼。
- 直向工作區、預覽／播放、基本單軌時間軸、素材選取、簡單剪頭尾。
- 最小專案資料結構從第一天沿用 V13 語意；基本草稿保護，尚不假裝完整支援 V13 專案編輯。
- 優先完成 720p／30fps 的單片 H.264＋AAC 匯出，原聲、方向、剪輯時間正確；完成後真能保存到 Files 或經分享流程交付。
- 顯示匯入／匯出階段、取消與重試。英文、日夜及手冊入口先有骨架。
- 同期做高風險小實驗：HEVC 取幀、1080p／4K 編碼能力、手機儲存、大型模型載入可能性、轉碼後端及 YT 工具架構。

**驗收門檻**

至少在一台真實 iPhone，以相簿／Files 匯入含原聲影片，剪掉頭尾，輸出並在 Files／照片可用的播放流程重新播放，證明畫面、方向、音訊與剪輯長度正確。Safari 及主畫面模式分別記錄。只有 Canvas 播放或下載空檔不算完成。

**交付**：可操作 build、測試影片屬性、實機／iOS 記錄、成功與失敗流程、能力探測表、後續缺口。此階段不宣稱 V13 功能完成。

### 第二階段：可靠專案＋多軌剪輯

- 新建／開啟／儲存／另存／匯出 nvproj、草稿回復與不覆蓋範例。
- 雙影音軌、圖片軌、留白、片段移動／裁切／分割、Undo／Redo、精確時間與手機手勢。
- 固定完整圖層資料模型，圖片同軌重疊與軌道順序；未完成的動畫／字幕欄位讀入後原樣保存，不可被清空。
- nvproj 大檔避免整檔多份 arrayBuffer 複製；素材按 Blob slice／串流讀取，先驗證 metadata 再取媒體。

**驗收**：桌面 V13 專案匯入手機、改一項時間、再匯回桌面；其餘資料及素材雜湊保留。正式「視覺完整互通」要等後續合成能力齊備，不能用本階段的資料保存代替。

### 第三階段：完整構圖、裁切、關鍵幀、轉場與調色

- 實作 F15–F23，包括保留框外、零直徑、起終點與緩動、內扣／外加所有時間語意。
- 套用完整轉場／風格列舉，選單要可預覽。
- 先建立共用的兩點動畫控制元件，第四階段再接上標題與動畫效果。
- 起點／終點配色、九宮格、旋轉數字與精確微調都要適合觸控。

**驗收**：同一測試專案在起點、中間、終點、轉場邊界與空白區，手機預覽／成品／V13 參考結果一致；不能只有 UI 數值可改但匯出沒套用。

### 第四階段：標題、雙字幕軌與動畫素材

- 完整標題樣式與進退場、GIF／PNG、自帶 240 組效果、兩種文字工作流。
- 字幕編輯器採全螢幕可搜尋列表；輸入法組字、鍵盤出現、游標及返回位置可靠。
- 完成圖片／動畫／標題的 V13 同軌重疊與跨軌 L 排序。預覽選到前方／後方物件都能操作。
- 字型需實測 iPhone 可用性；可研究有授權的內建字型及使用者匯入字型。不能直接打包 Windows 字型，缺字型時清楚提示替代。宣稱像素一致的測試必須使用同一字型資產。
- 整合第三階段的構圖、起終點關鍵幀、快速對位。

**驗收**：疊三個同軌物件改起始時間後覆蓋順序正確；GIF 分割前後連續；頂層新增字幕不顯示／修改底層全部字幕；匯出與重開專案均保留結果。

### 第五階段：音軌與完整混音

- 多音軌、素材 offset、循環／接縫淡化、淡入淡出、原聲控制與音量曲線。
- 41 首配樂庫及自己的音檔；試聽、加入、分類搜尋與下載。
- 用共用音量計算產生預覽與匯出結果；長音訊避免完整多軌解碼後再複製。
- 以使用者點按恢復 AudioContext，處理耳機切換與來電等中斷；試聽不能重疊播放一堆曲目。

**驗收**：一個含雙影片原聲、兩條配樂、循環接縫及 ducking 曲線的專案，預覽和輸出音量／時間相符。由人實際聽過，不能把 RMS／峰值分析寫成已完成聽感驗收。

### 第六階段：AI 字幕完整移植

- 所有既有模型與語言／範圍／文字處理選項，先做 base 路徑，再依設備驗證 small／Turbo 等。
- 預設一般 30 秒／重疊 5 秒；短分段 20 秒／重疊 2 秒由使用者選，不依單支影片自動替換全域預設。
- 保留追加／取代的明確說明：V13 的取代會影響全部舊字幕，不能讓使用者以為僅替換一軌。
- 保留音軌只辨識使用範圍與第一輪、影片辨識原聲及分軌的規則。
- 模型與媒體編碼不能任意並行耗盡記憶體；載入前提供下載／儲存資訊，完成或取消可釋放資源。
- 記錄實際模型、後端、檔案讀取、初始化、分段；取消終止 Promise 和舊計時器。不得用「沒有進度」直接判斷手機太弱。

**驗收**：短句、長片、長停頓、背景噪音、中英混合、連續重跑與取消後重試。測到手機無法跑的模型要列為未完成能力，不能移除模型選項後宣稱全模型對齊。第一階段的探測應已指出需要處理的資源瓶頸。

### 第七階段：相容轉碼與獨立工具

- 轉碼保留原尺寸／1080p、HDR→SDR、原檔保護、片段替換及 Undo／Redo。
- V13 桌面工具的 512 MB 等限制是既有實作邊界，不是 iPhone 已驗證能處理的保證；測試後記錄實際邊界和剩餘缺口。
- YT → MP3 依先前確認架構實作，不把 Windows helper 直接指向手機 localhost。
- 工具獨立開啟、返回編輯器、結果匯入的流程完整；與手冊一樣保留明確入口。

**驗收**：工具真能完成使用情境，服務需求／資料流／失敗處理清楚。單純顯示入口、Windows 安裝說明或「改用電腦」不等於手機功能完成。若仍需要架構決策，本階段不得標為完成。

### 第八階段：輸出規格、可靠性與 V13 全面對齊

- 補齊 V13 專案原有解析度／比例／fps／bitrate、4K、MP4 與既有 WebM 路徑；各組合以真實支持狀態呈現。
- 大型專案、長片、低可用儲存、背景中斷、跨版本升級、離線快取與專案回復。
- 手冊手機版完成，工具與素材下載說明不再出現「Ctrl＋滾輪」「右鍵」「Windows 選資料夾」作為唯一做法。
- 對 F01–F45 每列核對：完成證據、裝置、限制、回歸測試、與 V13 比較結果。
- 使用者在真實 iPhone 確認完整流程，再建立手機正式版及獨立重要還原點；桌面 V13 還原點保持原樣。

**完成條件**：沒有以隱藏功能、丟棄資料、默默降低輸出或必須改在桌面操作來冒充完成的項目。若純本機 Web App 有無法跨越的能力差距，列成明確缺口；只有使用者同意調整需求後才修改驗收定義。

## 7. 必須保存的 V13 規則

1. L1 影片底層與其字幕先合成，再合成 L2 影片頂層與其字幕；圖片／動畫／標題依各自 L 順序。手機可以改時間軸顯示方向，不可因此反轉合成規則。
2. V13 同軌重疊主要新增在圖片／動畫／標題，不能自行推論成影片同軌也可任意重疊，或字幕同軌所有句都一起顯示。
3. 內扣／外加是每段轉場取幀與時間語意，不是「連續／不連續」開關。
4. 關鍵幀目前是起點→終點；使用者未要求多點系統。不可拿做多點新功能延遲現有功能對齊。
5. 上方快速對位在有動畫時可平移整段起終點路徑，終點九宮格只改終點；不要改成兩個九宮格都覆寫同一份座標。
6. 裁切形狀與保留內／外在片段中固定；大小與中心可動畫。圓直徑 0 的內／外保留結果不同。
7. 範例初次儲存必須成為使用者副本。已有專案內嵌的 GIF／配樂不因素材库更新而替換。
8. 音軌順序只是列表整理，所有音軌都混音；視覺被覆蓋不等於靜音。
9. AI 一般模式保留原設定；短分段是可選補救，不能因一支片有效就全域特調。不可把下載完單一模型檔描述成整套已初始化完成。
10. 專案存檔、影片編碼完成、匯出交給分享、確實保存到外部檔案是不同狀態，不能使用同一個「已儲存」訊息。

## 8. 實機驗收與測試資料

### 裝置與模式

先盤點實際可取得的 iPhone 型號與 iOS。建議至少覆蓋一台較低資源的目標機、一台較新的機型；普通與大螢幕、Safari 與主畫面模式、直向／橫向都要測。具體最低機型及系統由第一階段數據決定，不在文件中假裝已通過。

桌面 Chrome 的手機尺寸模擬只能驗證部分排版；Playwright WebKit 可輔助回歸，**不能代替 iPhone 的硬體編碼、分享、相簿、系統中斷與記憶體測試**。沒有真機，就把真機項目標為待驗證。

### 共用測試專案組

| 組別 | 內容 |
|---|---|
| A 基本影音 | H.264／AAC、橫直拍、靜音片、不同 fps、VFR、相簿／Files／尚未下載的 iCloud 素材 |
| B 圖層 | 兩影片＋雙字幕＋圖片＋GIF＋標題；每種同軌重疊、相同／不同起始時間、透明露底 |
| C 動畫 | 所有轉場／標題動畫 ID；內扣／外加、裁切內外、零尺寸、−360→360、菱形範圍 |
| D 音訊 | 雙原聲、循環、接縫、淡化、曲線、不同取用起點；有中間停頓的旁白 |
| E 專案 | V13→手機→V13；素材雜湊、無變更重存、只修改單一屬性、範例保護 |
| F 壓力與失敗 | 720p／1080p／4K，短／長素材、低儲存、斷網、取消、鎖屏、背景、更新中止 |
| G 工具 | HEVC／HDR 轉碼、替換片段與復原、YT 工具端不可達／取消／結果匯入 |

每個素材需有來源／授權記錄。優先使用合成或已授權測試資料；目前使用者私有影片只在本機排查，不放公開 GitHub。

### 驗收記錄

- 狀態分成：已通過、未完成、失敗、待真機、平台限制待決策；「有按鈕」不算已通過。
- 記錄 build／commit、型號、iOS／瀏覽器、入口模式、素材與輸出規格、流程、預期／實際、錯誤。
- 同專案抽查片頭／片尾、每個轉場中點、關鍵幀邊界、重疊開始／結束、留白及音量節點。
- 比較解碼後的畫格、時間與聲音，不要求不同編碼器輸出 MP4 的二進位雜湊相同。素材與專案內嵌來源則應核對雜湊。
- 相同字型時比較文字位置；缺字型要先記錄替代，不能用任意放宽像素容差掩蓋錯誤。
- 把既有 `overlap`、`dual-track`、`crop`、`motion`、`end-align`、`subtitle-scope`、`volume-curve`、`asr-recovery`、`rotation-save` 等測試轉成核心／手機適配測試；沿用案例，重寫滑鼠專屬操作。
- 先制定可接受的時間／像素／音訊誤差，再測試；不要看結果後任意放寬。
